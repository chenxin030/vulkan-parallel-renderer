# ADR-0001: 项目定位

> 状态：已确定

## 问题

求职指南指出"从头写 Renderer 是无效项目"，建议"基于商业引擎做深度改造"。为何还做自研引擎？

## 方案对比

| 方案 | 描述 | 评估 |
|------|------|------|
| 只做商业引擎改造 | UE/Unity 深度改造 | 安全，但无法展示 Vulkan API 能力 |
| 只做自研引擎 | 从头写 Renderer | 有风险（指南说无效），但能证明底层能力 |
| **两者都做** ✅ | 本项目 = Vulkan 能力证明；商业引擎改造另起项目 | 互补，覆盖两种面试需求 |

## 选择：两者都做 + 深度优先

- 本项目定位为 **Vulkan API 能力证明**（vk::raii、Dynamic Rendering 等现代特性）
- 商业引擎改造（UE/Unity）另起一个项目，两个项目互补
- 遵循指南核心铁律：**深度 > 广度**，必须有量化数据

## 简历策略

- 按 **STAR-B** 格式组织项目描述（Situation / Task / Action / Result / Business Impact）
- 标题公式：`[技术领域] + [解决的问题] + [量化结果]`
- 选 2–3 个深度点展开，其余简要提及
